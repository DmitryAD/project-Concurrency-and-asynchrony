# project-Concurrency-and-asynchrony

Учебный проект: асинхронный веб-краулер на Python.
Семь этапов, каждый усложняет предыдущий.

## Стек

- `asyncio` — асинхронное программирование
- `aiohttp` — асинхронный HTTP-клиент
- `aiofiles` — асинхронная работа с файлами
- `beautifulsoup4` + `lxml` — разбор HTML

## Структура

```
.
├── crawler/              # пакет с кодом краулера, растёт от дня ко дню
│   ├── __init__.py       # публичный API пакета
│   ├── async_crawler.py      # загрузка страниц и обход сайта
│   ├── html_parser.py        # разбор HTML
│   ├── crawler_queue.py      # очередь URL с приоритетами
│   ├── semaphore_manager.py  # лимиты: общий и на домен
│   ├── rate_limiter.py       # частота запросов, паузы, backoff
│   ├── robots_parser.py      # разбор и соблюдение robots.txt
│   ├── errors.py             # типы ошибок и их классификация
│   ├── retry_strategy.py     # повторы с экспоненциальным backoff
│   └── circuit_breaker.py    # временная блокировка «лежащего» домена
├── demos/                # демонстрации и проверки по дням
│   ├── __init__.py
│   ├── demo_day1.py
│   ├── demo_day2.py
│   ├── demo_day3.py
│   ├── demo_day4.py
│   └── demo_day5.py
├── tests/                # сквозная проверка всех дней
│   ├── __init__.py
│   └── check_all.py
├── docs/                 # разбор заданий по дням
│   └── day1.md
├── requirements.txt
└── .gitignore
```

Пакет `crawler/` один на весь проект и меняется от этапа к этапу.
Состояние на конец каждого дня помечается тегом git — см. ниже.

## Установка

```bash
python -m venv .venv

# Windows
.venv\Scripts\activate
# macOS / Linux / Codespaces
source .venv/bin/activate

pip install -r requirements.txt
```

В GitHub Codespaces виртуальное окружение не обязательно —
контейнер сам по себе изолирован, достаточно `pip install`.

## Запуск

Из корня репозитория, через флаг `-m`:

```bash
python -m demos.demo_day1
python -m demos.demo_day2
python -m demos.demo_day3
python -m demos.demo_day4
python -m demos.demo_day5
```

**Почему `-m`, а не `python demos/demo_day1.py`.** Python при запуске
скрипта добавляет в пути поиска модулей папку самого скрипта — то есть
`demos/`. Пакета `crawler` там нет, и импорт падает с `ModuleNotFoundError`.

Флаг `-m` запускает файл как модуль пакета: в пути попадает текущая
директория, то есть корень проекта, и `crawler` находится. Побочный
эффект — файл обязан лежать в пакете, поэтому в `demos/` есть
`__init__.py`.

## Проверка, что ничего не сломалось

```bash
python -m tests.check_all
```

Прогоняет ключевые требования всех готовых дней на локальном тестовом
сервере, интернет не нужен. Каждая проверка печатается с ✓ или ✗,
в конце итог. Запускать после любого изменения в `crawler/`. Новый день
считается готовым, только когда проверки всех предыдущих дней тоже зелёные.

### Как ставить теги

В конце дня, после коммита:

```bash
git tag -a day2 -m "День 2: парсинг HTML и извлечение данных"
git push origin day2
```

Вернуться к состоянию любого дня:

```bash
git checkout day1        # посмотреть
git checkout main        # вернуться обратно
```

Сравнить, что изменилось между днями:

```bash
git diff day1 day2
```
